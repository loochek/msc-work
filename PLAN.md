## План работы над темой

#### Что сделано

1. Изучение темы, предметной области, теории
- Изучена общая проблематика сканирования уязвимостей в OCI-образах
- Изучены спецификации OCI, описывающие форматы хранения образов и API container registry, также рассмотрены особенности хранения образов на стороне container registry
- Зафиксирован интересующий модельный пример нагрузки - managed container registry облачного провайдера 

2. Анализ существующих решений
- Произведен обзор существующих решений - Trivy, Clair
- Протестирован и изучен популярный сканер уязвимостей Trivy

3. Постановка проблемы, определение пути решения
- Изучен процесс сканирования образа в связке Harbor container registry + Trivy
- Выявлены недостатки в схеме взаимодействия компонентов, не позволяющие производить анализ максимально эффективно
  - недостаточно тесная интеграция сканера с container registry, что приводит к лишнему оверхеду
  - отсутствие персистентного кеширования результатов анализа
- Предложены конкретные идеи касательно архитектуры целевого решения, позволяющие решить выявленные недостатки
  - прямая работа сканера с blob storage/ФС container registry для получения содержимого образов
  - персистентное хранение SBOM для слоев в blob storage + метаинформация в Postgres

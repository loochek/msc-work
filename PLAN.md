## План работы над темой

#### Что сделано

1. Изучение темы, предметной области, теории
- Изучена общая проблематика сканирования уязвимостей в OCI-образах
- Изучены спецификации OCI, описывающие форматы хранения образов и API container registry, также рассмотрены особенности хранения образов на стороне container registry
- Зафиксирован интересующий модельный пример нагрузки - managed container registry облачного провайдера

2. Анализ существующих решений
- Произведен обзор существующих решений — Trivy, Clair, Grype
- Протестированы и изучены сканеры Trivy и Clair
- Изучен формат eStargz: структура архива и TOC

3. Постановка проблемы, определение пути решения
- Изучен процесс сканирования образа в связке Harbor + Trivy
- Выявлены недостатки:
  - при сканировании из registry Trivy скачивает слои целиком, хотя для анализа нужна лишь малая его часть
- Выбран вектор реализации: ленивая загрузка слоёв через eStargz как способ минимизировать сетевой трафик

4. Разработка прототипа
- Реализован форк Trivy с поддержкой ленивой загрузки слоёв в формате eStargz: сканер скачивает только файлы, необходимые для анализа

5. Сравнение с изученными решениями, выводы
- Разработан инструментарий для воспроизводимого бенчмарка: генерация тестового набора образов,
  конвертация в eStargz, запуск сканеров, верификация корректности результатов, визуализация
- Проведён бенчмарк на тестовом наборе образов, моделирующем профиль нагрузки на container registry
